# Per-service environment allowlist — the machine-checked half of the env
# contract (the prose half is ENVIRONMENT_VARIABLES.md).
#
# Enforced by ./check-service-env.sh, which renders docker-compose.yml to JSON
# and asserts every service's environment KEY NAMES (never values) are a subset
# of its section here. Adding a key to a service in docker-compose.yml without
# adding it here fails the check.
#
# Subset, not equality: a key listed here but absent from .env legitimately does
# not reach the container (bare `- KEY` entries in compose stay unset), so
# optional overrides can be listed without forcing them into every environment.
#
# Sections are compose SERVICE names. An empty section means "no environment at
# all". Blank lines and #-comments are ignored.
#
# Background (P10): all six app services used to share `env_file: .env.runtime`,
# so each got all ~101 production values — the internet-facing frontend held
# DATABASE_URL, POSTGRES_PASSWORD, JWT_SECRET, WORKER_AUTH_TOKEN, the SES/S3/
# backup keys, CLOUDFLARE_DNS_API_TOKEN and GCLOUD_RW_API_KEY while sharing a
# network with postgres.
