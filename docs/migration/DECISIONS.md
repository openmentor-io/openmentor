| D32 | Traefik v2 -> v3 | **Upgraded to traefik:v3.7 and moved the HTTP->HTTPS redirect to the entrypoint** (Dependabot #4 proposed the image bump alone, which would have shipped broken). Two problems, both pre-existing: (1) the `http-catchall` router used the v2 named-group matcher ``hostregexp(`{host:.+}`)``, and v3 regexp matchers take Go regexp syntax — v3 offers `--core.defaultRuleSyntax=v2` as a compatibility escape hatch, but it is deprecated and slated for removal in the next major, so the rule was migrated rather than pinned; (2) more importantly the router never existed at all — it was declared as labels on the `traefik` container itself, and with `--providers.docker.exposedbydefault=false` the docker provider only builds routers for containers carrying `traefik.enable=true`, which traefik's own container does not. So the "Redirect HTTP to HTTPS globally" comment never described reality: plain :80 traffic for the canonical domain was served by the `frontend` router (Traefik breaks priority ties by rule length, and `Host(...) \|\| Host(www...)` is longer than the catch-all's rule), i.e. the site answered over unencrypted HTTP. Replaced with `--entrypoints.web.http.redirections.entrypoint.{to=websecure,scheme=https,permanent=true}` — static config, so it is immune to provider label filtering and involves no rule syntax at all. The now-unreachable plaintext `frontend` router was dropped. Safe to blanket-redirect :80 because ACME uses DNS-01 (an HTTP-01 challenge would need `/.well-known/acme-challenge` carved out). Dev overlay is unaffected: it replaces `command` wholesale and stays HTTP-only | DECIDED (2026-07-31) |
